# Lecture Notes
## Praxis Framework
Overall; recall that praxis is the following framework: 
* Framing: Defining an opportunity with stakeholders (w/requirements) 
	* Stakeholders in general include everyone that would be affected with this project. 
* Diverging: Exploring a wide array of ideas and alternatives to solve the Framed opportunity. 
* Converge: Making decisions and justifying recommendations, that is whittling down concepts formed from divergence. 

The goal of the Praxis Framework is to ultimately combine all of these, 
## Overall Language
(These are mainly takeaways from Tutorials)
* "Must" should not be an alternative to "Shall". 
	* Must defines an external condition; 
	* Shall is a mandatory condition that needs to be a part of the design.
* "Can" implies a different set of permissions than "may"
	* Can is more superfluous/dependent on external factors; may is pre-approved.

## Problem Solving
Generally; we can define Engineering within a matrix of a table: 

| 0 / Multiple Approaches | Open-Ended problems<br>(i.e. puzzles) | Engineering<br>(Design Challenges)          |
| ----------------------- | ------------------------------------- | ------------------------------------------- |
| 1 Approach              | **Closed** Problems.                  | Open-Ended Problem<br>(i.e. Investigations) |
| N/A                     | 1 Solution                            | 0  / Many Solutions                         |
* With 1 approach and solution; problems are a set path to a set goal. These are like your math equations. 
* With 0/Multiple approaches and one solution; we get a set of divergent methods that converge to the same overall goal (puzzles). 
	* e.g. multiple ways to solve a single problem
* With 1 approach with 0 / multiple solutions; we get a convergent method leading to divergent outcomes. (investigations)
* With 0/multiple approaches with 0/many solutions; we get Engineering (present in design problems)
	* i.e. many ways to solve many different things. 

## Models
Also see: [[1 — Lecture Stuff | Lecture 01 (CIV102)]]
1. No model is perfect; all are simplifications with the intent to be *useful*. 
2. Different models allow one to perceive / understand the same situation differently. 
3. Some models are *predictive* (i.e. risk assessment), some are explanatory. 

The goal of praxis is to *use these models* to inform and improve our actions within the world; especially with the projects that we build to affect the greater community. 
**Engineers create and justify decisions.**
### Black-Box Model
Given two sets of objects: The World as it Is; and the world as we perceive it ($W_{G}$ and $W_{I}$): 
* A Model maps $W_{G}\mapsto W_{I}$; or it maps the global world and the perceived world. 
* The world that we dream of ($W_{D}$) is inherently solely related with $W_{I}$. 

The relationship between $W_{D}$ and $W_{I}$ (Imagined and Dreamed world via model) is located in the superset of Theories; such as Science, Math, Humanities, etc.) 

We can map $W_{D}$ to a world we create ($W_{C}$) by the function of Building: 
* $W_{D} \mapsto W_{C}$

$W_{C}$ is related to $W_{G}$; where our designs / creations are built into the world as it is; leaving an **impact**. 

* $W_{C} \to W_{G}$ via Impact 

Or; in summary: 
* $W_{G} \mapsto W_{I}$ via Models
* $W_{I} \leftrightarrow W_{D}$ via Designs 
* $W_{D} \mapsto W_{C}$ via Building
* $W_{C} \leftrightarrow W_{G}$ via Impact 
* $W_{G} , W_{C} \in \text{ Reality }$
* $W_{D}, W_{I} \in \text{ Theory}$
	
Or; The world is perceived by us as models into our imagined world; we dream change in our imagined world by design; we put this change into the world by building; and this leaves an impact into the global world.
